# 1. 产品概述

## 1.1 产品定位

LassoClip 是一款面向网页内容的视觉剪藏与素材创作浏览器插件。

用户可以从任意网页中自由提取视觉内容，通过自由手绘、多边形选择和智能 DOM
元素识别等方式截取所需区域，并将多个视觉片段组织成可编辑、可组合、可追溯和可复用的视觉素材。

LassoClip 不只是一个截图工具，而是一个轻量级的网页视觉素材工作空间。

**产品核心价值：**

-   自由提取：突破传统矩形截图限制，支持任意形状剪藏。
-   智能识别：自动识别网页图片、文字块、卡片和其他 DOM 元素。
-   视觉创作：支持多个独立素材组合、图层编辑和视觉装饰。
-   素材沉淀：保存剪藏历史、原始网页来源和用户备注。
-   高效复用：一键复制、透明 PNG 导出和素材分享。

**产品 Slogan：**

Capture anything. Shape it. Reuse it.

## 1.2 目标用户

1.  科研人员：截取论文中的架构图、实验结果、表格和关键文字。
2.  学生：收集学习资料、网页插图和技术文档内容。
3.  设计师：提取网页 UI、图片、组件和设计参考。
4.  开发者：收集代码片段、技术架构图和错误信息。
5.  普通办公用户：整理网页信息、制作说明图片和汇报素材。

## 1.3 产品设计原则

-   Local-first：优先本地处理和本地存储。
-   Privacy-first：不默认上传用户截图，不强制注册。
-   Lightweight：快速启动、快速截图、快速复制。
-   Non-destructive
    Editing：尽可能采用非破坏性编辑，保留素材和标注的独立性。
-   Source Traceability：每个剪藏素材都尽可能保留原始网页来源。
-   Progressive Enhancement：先完成稳定的基础功能，再逐步引入 AI。

# 2. 产品功能架构

LassoClip 由四个核心模块组成。

## 2.1 Visual Capture --- 智能视觉剪藏

负责从网页中提取视觉内容。

主要功能：

-   自由手绘截图
-   多边形截图
-   矩形截图
-   椭圆截图
-   智能 DOM 元素吸附
-   放大镜和精确选区
-   冻结画面
-   透明背景裁剪
-   边缘抗锯齿

## 2.2 Clip Studio --- 视觉编辑与组合

负责对剪藏素材进行编辑和重新组织。

主要功能：

-   多区域连续剪藏
-   独立图层
-   自由画布
-   自动排版
-   图片拖动、缩放、旋转
-   图层顺序管理
-   文字、箭头、画笔和高亮
-   马赛克和敏感信息遮挡
-   背景、圆角、阴影和边框

## 2.3 Clip Library --- 视觉素材管理

负责素材的保存、组织、搜索和来源追溯。

主要功能：

-   自动保存剪藏历史
-   素材预览
-   素材重命名
-   用户备注
-   标签和收藏夹
-   来源网页记录
-   OCR 全文检索（后续版本）

## 2.4 Export & Share --- 导出与复用

负责将剪藏素材输出到其他应用。

主要功能：

-   复制到剪贴板
-   PNG 导出
-   JPG 导出
-   WebP 导出（后续版本）
-   拖拽导出
-   PDF 导出（后续版本）
-   Markdown 导出（后续版本）
-   分享链接（长期版本）

# 3. 核心交互模式

LassoClip 必须同时支持两种工作模式。

## 3.1 Quick Clip --- 快速剪藏

目标：用户在几秒内完成一次截图，不需要进入复杂编辑器。

操作流程：

1.  用户通过快捷键、扩展图标或右键菜单启动剪藏。
2.  当前网页进入截图模式。
3.  用户选择截图类型。
4.  用户完成区域选择。
5.  系统自动生成对应的图像。
6.  自动复制到系统剪贴板。
7.  保存至本地剪藏历史。
8.  显示轻量级操作反馈。

截图完成后提供以下操作：

-   复制图片
-   保存 PNG
-   进入编辑器
-   再次截图
-   查看来源

默认行为：

-   输出 PNG。
-   不规则选区以外的区域保持透明。
-   自动复制到剪贴板。
-   自动保存到本地历史。
-   保留网页 URL、标题和截图时间。

Quick Clip 不应强制打开完整编辑器。

## 3.2 Clip Board --- 视觉素材组合

目标：用户从同一个或多个网页中提取多个视觉区域，统一进行组织和编辑。

操作流程：

1.  用户启动 Clip Board。
2.  用户连续执行多次截图。
3.  每次截图生成一个独立 Clip Item。
4.  素材进入当前项目。
5.  系统自动排列素材。
6.  用户可以切换自由布局。
7.  用户编辑、组合和标注素材。
8.  导出最终图片。
9.  项目保存至本地。

默认支持：

-   每个素材独立移动。
-   每个素材独立缩放。
-   每个素材独立旋转。
-   图层顺序调整。
-   删除、复制素材。
-   修改画布背景。
-   自动排版与自由布局切换。

**核心要求：Quick Clip 和 Clip Board
必须共享同一套截图引擎和素材数据模型，避免重复实现。**

# 4. 功能详细需求

优先级定义：

-   P0：MVP 必须实现。
-   P1：第一阶段完成后的增强功能。
-   P2：长期规划。

## 4.1 Visual Capture

### FC-001 自由手绘选区（P0）

用户通过鼠标自由绘制任意形状的闭合选区。

交互要求：

-   鼠标按下开始绘制。
-   鼠标移动实时显示路径。
-   鼠标释放后闭合选区。
-   支持取消和重新绘制。
-   支持确认当前选区。
-   路径闭合应平滑，不出现明显锯齿。
-   支持边界附近的精细操作。

输出要求：

-   按照选区轮廓裁剪图像。
-   选区以外的像素 Alpha 必须为 0。
-   保留原始像素比例。
-   不得简单使用矩形裁剪代替真正的透明形状裁剪。

### FC-002 多边形截图（P0）

用户通过多个顶点构建选区。

交互要求：

-   单击添加顶点。
-   鼠标移动显示当前边。
-   双击或点击起点闭合。
-   支持删除上一个顶点。
-   支持取消操作。

### FC-003 矩形与椭圆截图（P0）

提供标准几何选区。

支持：

-   鼠标拖动绘制。
-   按住 Shift 保持比例。
-   拖动控制点调整大小。
-   选区确认和取消。

### FC-004 智能 DOM 元素吸附（P0）

当鼠标移动至网页元素时，系统自动识别当前元素的边界。

首期支持：

-   图片 img。
-   SVG 图形。
-   文字容器。
-   卡片容器。
-   表格。
-   常见内容块。

交互：

1.  鼠标悬停在元素上。
2.  系统计算元素边界。
3.  显示边界高亮。
4.  用户点击确认。
5.  截取对应区域。

技术要求：

-   使用 DOM API 获取元素。
-   获取 getBoundingClientRect。
-   处理滚动偏移和页面缩放。
-   考虑嵌套元素。
-   避免父子元素之间频繁抖动。
-   提供手动调整边界的能力。

智能吸附不得影响普通手绘截图。

### FC-005 放大镜与精确选区（P0）

提供局部放大镜辅助用户精确选择。

要求：

-   跟随鼠标移动。
-   展示鼠标附近的局部图像。
-   显示选区坐标辅助线。
-   支持键盘微调选区。

### FC-006 冻结画面（P0）

截图前先获取当前可见视口的静态图像，随后在冻结的静态图像上完成选区绘制。

目标：

避免网页滚动、动画和悬浮菜单变化影响选区准确性。

要求：

-   冻结当前可见区域。
-   在静态图像上执行自由选择。
-   保持页面原始状态，不影响网页交互状态。
-   用户取消后退出截图模式。

### FC-007 透明背景输出（P0）

所有不规则选区必须支持透明背景。

要求：

-   使用 Canvas Path 或等效方式执行真实 Alpha 裁剪。
-   支持 PNG 导出。
-   边缘具有抗锯齿。
-   不允许将透明区域填充为白色。
-   保证不同 DPR 和页面缩放下的裁剪准确性。

### FC-008 快捷键与启动入口（P0）

提供：

-   浏览器扩展图标。
-   快捷键启动。
-   右键菜单启动。
-   快速截图入口。
-   组合编辑入口。

快捷键应允许用户通过 Chrome 扩展快捷键设置修改。

## 4.2 Clip Studio

### CS-001 多区域连续剪藏（P0）

用户可以连续执行多次截图。

每次截图生成一个独立素材，不覆盖之前的素材。

### CS-002 独立图层（P0）

每个素材必须作为独立对象存在。

支持：

-   移动。
-   缩放。
-   旋转。
-   删除。
-   复制。
-   调整层级。

### CS-003 自由画布（P0）

提供可视化编辑画布。

要求：

-   支持缩放和平移。
-   支持多个素材同时存在。
-   支持选中和多选。
-   支持拖动和调整大小。
-   支持对齐辅助线。
-   支持撤销和重做。
-   支持画布背景设置。

### CS-004 自动排版（P0）

新加入的素材默认采用自动排版。

要求：

-   根据素材宽高比进行合理排列。
-   避免素材重叠。
-   保持统一间距。
-   支持调整排列间距。
-   支持一键切换到自由布局。

自动排版不依赖 AI，使用确定性布局算法实现。

### CS-005 基础标注（P0）

支持：

-   文字。
-   箭头。
-   直线。
-   矩形。
-   椭圆。
-   画笔。
-   高亮区域。

标注应当与原始素材分离，支持独立修改。

### CS-006 敏感信息遮挡（P0）

支持：

-   模糊。
-   像素化。
-   实色遮挡。

安全要求：

-   最终导出图片必须将遮挡效果真正写入像素。
-   不得仅通过隐藏标注图层实现遮挡。
-   导出文件不得包含可恢复的被遮挡原始内容。
-   遮挡区域应清晰可见。

### CS-007 视觉装饰（P1）

支持：

-   圆角。
-   阴影。
-   边框。
-   纯色背景。
-   渐变背景。
-   外边距。
-   样式预设。

### CS-008 图层管理（P0）

提供独立图层列表。

支持：

-   上移。
-   下移。
-   置顶。
-   置底。
-   隐藏。
-   删除。
-   锁定。

## 4.3 Clip Library

### CL-001 自动保存（P0）

每次成功剪藏后自动保存到 IndexedDB。

不得因为关闭弹窗或刷新网页而丢失已经完成的剪藏记录。

### CL-002 素材预览（P0）

提供素材缩略图列表。

显示：

-   缩略图。
-   素材名称。
-   创建时间。
-   来源网站。
-   素材类型。

### CL-003 来源追溯（P0）

每个素材尽可能记录：

-   原始 URL。
-   网页标题。
-   域名。
-   截图时间。
-   选区类型。
-   原始元素文本（可获取时）。

允许用户通过来源链接返回原始网页。

不得将用户主动截取的网页内容上传服务器。

### CL-004 重命名与备注（P0）

支持：

-   修改素材名称。
-   添加用户备注。
-   删除素材。
-   收藏素材。

### CL-005 标签和收藏夹（P1）

支持：

-   创建标签。
-   多标签关联。
-   创建收藏夹。
-   将素材移动至收藏夹。
-   根据标签筛选。

### CL-006 OCR 搜索（P1）

对图片进行本地 OCR。

支持：

-   提取文字。
-   保存 OCR 结果。
-   根据文字搜索素材。
-   显示文字识别结果。

### CL-007 智能分类（P2）

根据图片内容自动生成分类和标签。

必须作为可选功能，不能成为基础剪藏流程的依赖。

### EX-001 剪贴板复制（P0）

要求：

# 5. 页面结构与 UI 信息架构

浏览器扩展点击后的轻量入口。

-   LassoClip Logo。
-   Quick Clip。
-   Clip Board。
-   最近剪藏。

设计原则：

# 6. 技术架构

## 6.1 技术栈

  层级             技术
  ---------------- ------------------------------
  浏览器扩展       Chrome Extension Manifest V3
  扩展开发框架     WXT
  前端框架         React
  编程语言         TypeScript
  样式             Tailwind CSS
  UI 组件          轻量化自定义组件
  截图与图像处理   Canvas API
  选区路径         SVG / Canvas Path
  本地数据库       IndexedDB
  扩展状态         Zustand 或轻量状态管理
  图像处理         Canvas 2D
  构建工具         Vite（由 WXT 管理）

技术选型原则：

-   不引入不必要的重量级依赖。
-   图像处理尽量使用浏览器原生能力。
-   核心功能不依赖远程 API。
-   所有数据模型使用 TypeScript 类型约束。
-   保证未来可以扩展更多编辑能力。

## 6.2 系统架构

采用以下分层结构：

1.  Extension Layer：负责浏览器扩展入口、快捷键和生命周期。
2.  Capture Layer：负责网页截图、DOM 识别和选区交互。
3.  Image Processing Layer：负责裁剪、透明背景、图像合成和导出。
4.  Editor Layer：负责画布、图层、标注和交互。
5.  Storage Layer：负责本地素材、项目和元数据。
6.  UI Layer：负责 Popup、Editor、Library 和 Settings。

建议采用模块化目录结构：

``` text
│   ├── editor/

│
├── components/
│   ├── capture/
│   ├── editor/
│   ├── library/
│   └── common/
│
├── modules/
│   ├── capture/
│   ├── selection/
│   ├── dom-detection/
│   ├── image-processing/
│   ├── canvas-editor/
│   ├── annotation/
│   ├── export/
│   └── storage/
│
├── services/
│   ├── clipboard/
│   ├── browser/

│
├── hooks/
├── stores/
├── types/

```

以上为推荐结构。Codex
应结合实际项目情况调整，不得为了匹配目录示例而破坏合理的既有架构。

## 6.3 截图处理流程

基本流程：

1.  用户主动触发截图。
2.  扩展获取当前标签页可见区域。
3.  将截图作为临时图像。
4.  创建 Capture Overlay。
5.  用户完成选区。
6.  根据选区路径执行图像裁剪。
7.  输出透明 PNG 或其他目标格式。
8.  保存素材元数据。
9.  执行剪贴板复制或打开编辑器。
10. 清理临时资源。

建议由 Background Service Worker 协调截图任务，Content Script
负责网页交互，Extension Page 或适当的扩展上下文负责剪贴板与图像处理。

根据实际浏览器 API 限制选择合理的 Offscreen Document 或扩展页面方案。

必须特别处理：

-   设备像素比 DPR。
-   页面缩放比例。
-   滚动位置。
-   浏览器截图尺寸。
-   CSS 坐标与图像像素坐标转换。
-   截图与 Overlay 的坐标同步。
-   图片加载和异步渲染。

## 6.4 本地存储

使用 IndexedDB 保存图片和项目数据。

禁止将大尺寸图片直接存储在 Chrome Storage Sync 中。

Chrome Storage 可用于少量设置和配置。

# 7. 核心数据模型

必须使用 TypeScript 定义完整数据类型。

## 7.1 ClipItem

每一个独立剪藏素材。

建议字段：

``` ts
interface ClipItem {
  id: string;
  name: string;
  imageBlob: Blob;
  thumbnailBlob?: Blob;

  source: {
    url: string;
    title: string;
    domain: string;
    capturedAt: number;
    elementText?: string;
  };

  selection: {
    type:
      | "freehand"
      | "polygon"
      | "rectangle"
      | "ellipse"
      | "element";
    path?: Point[];
    bounds: Rect;
  };

  metadata: {
    width: number;
    height: number;
    format: string;
    createdAt: number;
    updatedAt: number;
  };

  tags: string[];
  notes?: string;
  favorite: boolean;
}
```

坐标和路径必须明确使用统一坐标系，建议保存为相对于裁剪区域的图像像素坐标或归一化坐标，并在类型中明确标识。

## 7.2 ClipProject

表示一个视觉组合项目。

``` ts
interface ClipProject {
  id: string;
  name: string;

  canvas: {
    width: number;
    height: number;
    background: string;
    layoutMode: "auto" | "free";
  };

  items: CanvasItem[];

  createdAt: number;
  updatedAt: number;
}
```

## 7.3 CanvasItem

表示画布中的一个独立对象。

``` ts
interface CanvasItem {
  id: string;
  clipId?: string;

  type:
    | "image"
    | "text"
    | "arrow"
    | "shape"
    | "drawing";

  transform: {
    x: number;
    y: number;
    width: number;
    height: number;
    rotation: number;
    opacity: number;
  };

  zIndex: number;
  visible: boolean;
  locked: boolean;

  style?: Record<string, unknown>;
}
```

## 7.4 Annotation

标注应与原始图像分离。

建议保存：

-   标注类型。
-   坐标。
-   样式。
-   文字内容。
-   层级。
-   创建时间。

避免每次修改标注都重新生成原始素材。

## 7.5 Storage Requirements

-   支持 IndexedDB 数据持久化。
-   图片采用 Blob 存储。
-   项目和图层使用结构化数据。
-   删除素材时正确清理关联数据。
-   支持应用重启后恢复项目。
-   对数据库结构设计版本迁移机制。

# 8. 权限与隐私要求

这是产品的重要设计约束。

## 8.1 最小权限

优先采用：

-   activeTab
-   scripting
-   storage
-   contextMenus
-   downloads（仅在确有需要时）

clipboardWrite、offscreen 等能力应根据实际实现选择。

不得默认申请所有网站的长期访问权限。

## 8.2 隐私原则

1.  不强制注册账号。
2.  不默认上传截图。
3.  不默认上传网页内容。
4.  不收集用户浏览历史。
5.  不在后台持续扫描网页。
6.  只在用户主动启动功能后访问当前页面。
7.  不默认保存整个原始视口截图。
8.  优先保存裁剪后的素材及必要的选区元数据。
9.  用户可以随时删除本地素材。
10. 明确告知用户截图可能包含网页中的个人信息。

## 8.3 技术限制

以下场景必须提供合理的降级方案：

-   chrome:// 等浏览器内部页面。
-   Chrome Web Store 等受保护页面。
-   部分跨域 iframe。
-   视频和 Canvas 等特殊内容。
-   Shadow DOM。
-   页面动态更新。
-   极长页面。
-   页面缩放和高 DPR。

不得声称插件能够无条件截取所有网页内容。

# 9. 非功能性需求

## 9.1 性能

建议目标：

-   扩展 Popup 打开响应：500ms 内。
-   截图模式启动：1s 内。
-   普通视口截图：2s 内完成。
-   普通尺寸选区裁剪：500ms 内完成。
-   剪藏完成后立即提供操作反馈。
-   不阻塞网页正常交互。

以上为目标测试指标，实际结果需要在不同设备和页面上验证。

## 9.2 稳定性

-   页面发生滚动时坐标正确。
-   页面缩放后坐标正确。
-   不因截图而修改网页原始布局。
-   取消截图时清理所有事件监听器。
-   重复触发不会创建多个冲突 Overlay。
-   图片过大时能够给出明确错误提示。

## 9.3 可维护性

-   TypeScript 严格模式。
-   模块职责清晰。
-   避免巨型组件。
-   图像处理与 UI 分离。
-   核心操作有单元测试。
-   关键浏览器交互有集成测试。
-   数据模型具有迁移能力。

## 9.4 UI/UX

视觉风格建议：

-   现代、简洁、精致。
-   避免传统浏览器插件的拥挤工具栏。
-   使用清晰的视觉层级。
-   编辑器以画布为中心。
-   工具栏尽量采用图标 + Tooltip。
-   关键操作有明确反馈。
-   适配不同浏览器窗口尺寸。

不要直接使用未经设计的默认组件堆砌界面。

# 13. MVP 最终交付标准

第一版产品交付时，应当能够完整演示以下场景：

**场景 A：快速自由形状截图**

打开任意普通网页 → 启动 LassoClip → 手绘不规则选区 → 生成透明 PNG →
自动复制到剪贴板 → 本地保存。

**场景 B：智能元素截图**

打开包含图片和文字的网页 → 鼠标悬停在图片上 → 系统自动识别边界 →
点击确认 → 输出对应素材。

**场景 C：多区域视觉组合**

打开一篇技术文章 → 截取架构图 → 截取关键文字 → 截取代码块 → 进入 Clip
Studio → 自动排列 → 手动调整 → 添加标注 → 导出完整图片。

**场景 D：素材历史管理**

完成多次剪藏 → 打开 Clip Library → 查看历史素材 → 搜索或筛选 →
查看原始网页来源 → 重新编辑或导出。

以上四个场景全部可以真实运行，且通过对应验收测试，才视为 MVP 完成。

# 14. 最终产品定义

LassoClip
的核心不是让用户拥有更多截图按钮，而是让用户以更自由、更自然的方式提取网页中的视觉内容，并将这些内容转化为能够持续编辑、组织和复用的数字素材。

第一版应当牢牢聚焦：

**自由剪藏 → 视觉组合 → 本地沉淀 → 高效复用。**

任何不直接服务于这条主线的功能，都应谨慎纳入 MVP。
